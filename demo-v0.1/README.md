# 衡智最小交互 Demo v0.1

## 当前增量：真实基金跟踪与两场景实验（2026-09-29）

以下旧介绍保留历史，当前能力以本段及源码为准。未调用LLM或真实银行，也不执行真实买卖。

- **理财跟踪**：五只真实货基000343/000359/000397/000389/000719，可勾选加入或移出跟踪，设置每日北京时间更新时间、手动更新。当前实例已开启09:00，新副本默认关闭。调度属于Python服务，无需Codex或浏览器持续打开；电脑/服务必须运行。每15秒检查，到时更新；失败最多当日3次、间隔1小时，重启补做当日错过任务。只支持首批五只，不是任意基金搜索。
- 来源为天天基金公开历史行情，不是腾讯接口；当前腾讯理财通在售、起购、赎回到账和完整费用未核实。页面区分数据日期与检查时间，旧数据不冒充当天数据，失败保留历史。9月29日首轮5/5成功，最新披露9月28日；近一年每只366个基线及日收益点。
- 四区间近1/3/6个月、1年；货基展示万份收益、七日年化、换算日收益率、再投资累计测算。未获取单位净值历史，明确空态，不伪造净值涨跌。日收益率不等于七日年化。
- 实际手动交易与模拟交易独立保存，买卖节点、确认/待确认、编辑/删除及并发版本校验。个人累计损益使用现金流和确认份额估算：假定1元份额、每日收益向下取分再投资；起始记录不全、基金实际结转/费用差异会影响结果，不能冒充平台确认盈亏。没有银行/腾讯账号同步，也没有下单。
- **账单分析实验**：输入`2026-09`或`2026`生成月/年确定性事实报告、JSON导出、逐笔依据。当前未结束期间对上个完整期间；缺期不计算差额。异常候选为同类前90天至少6笔历史的金额偏离、同日同金额同类同非空备注的疑似重复；反馈可标正常/需核查/信息不足，跨重启保留。规则结果不能认定欺诈，未接模型。
- **账单分析 JSON 契约（2026-10-13）**：`schemas/bill-analysis-facts-v1.json` 固化服务端事实层，`schemas/bill-analysis-narrative-v1.json` 固化未来模型解读层。当前手动账本没有独立商户字段和明确可用余额；金额按整数分，`net_cents` 不是余额。Schema 回归见 `test_bill_contract.py`；尚未接入 DeepSeek 或运行时校验。
- 填写当前现金、无重复预留总额、拟投入、用款日期和本金损失意愿后比较五只真实基金资料。现金由用户明确确认，不能从月结余推算。金额超限会阻断，渠道/交易资料不足会停在待补充，不生成订单。旧报告在账本修改/恢复后失效；改资金条件或刷新行情后需要重新比较。

存储：`data/funds.json`含调度、行情、实际/模拟交易与最近运行日志，`data/fund-sources/`保存最近原始来源；`data/analysis-feedback.json`保存核查反馈。仍是本机明文单用户文件。原账本JSON备份只覆盖账本，不包含新增基金记录/设置或核查反馈；完整迁移需停服务后备份整个data目录。没有跨机同步、自动开机启动或平台核验收益。

## 运行
Python 3.11+，无需安装第三方依赖。
在此目录执行 python server.py ，打开 http://127.0.0.1:18128 。
也可运行“启动演示.ps1”。测试：python -m unittest -v test_demo.py 。
数据：data/state.json；反馈：data/feedback.json。重置账户不会删除反馈。
手动账本：data/ledger.json。重置模拟账户不会删除手动记录或自定义分类。账本文件应自行备份；这是本机单用户研究原型。
仅本机使用，不公开部署，不输入真实敏感账单。可在自己的电脑现场试用或屏幕共享。

## 三分钟试用
### 独立账本与浏览器共享
- 账本保存在运行服务的电脑上，默认是 data/ledger.json，当前按明文 JSON 保存。
- 同一电脑的不同浏览器访问同一个服务，会读取同一份账本；页面可见时每 3 秒检查更新，切回页面也检查。自动更新保留当前月份和未保存表单，修改冲突仍由服务端拒绝。没有跨电脑云同步。
- 另一台电脑复制代码（不带原电脑的 data/ 目录），安装 Python 3.11+ 后运行 python server.py，即可从空账本开始；首次保存会生成该电脑的账本文件。
- 如需迁移旧账本，先停止两端服务，将旧 data/ledger.json 复制到新实例的数据目录；若目标已有账本，先单独备份。迁移后两台电脑各自的副本不会自动同步。
- 同机独立实例可使用 python server.py --port 18129 --data-dir data-personal-2；不同服务进程不要共用同一数据目录。

### 备份与恢复
在“我的账本”点击“备份账本”，下载明文 JSON，包含全部月份、备注和自定义分类，不包含银行模拟状态或反馈。换电脑后点击“恢复账本”选择该文件（最多 5 MB）。服务端校验后显示记录数，确认才替换整本账本，不是合并；确认后清空当前录入表单。

恢复前自动将旧账本保存为数据目录下 backups/before-restore-*.json；可选择该文件再次恢复。无效文件、未确认或预览后发生新记账均不会覆盖账本。备份文件不受加密保护；数据目录副本与下载文件需自行保管。备份恢复不等于银行账单导入。

### 先试手动记账
明细按日期倒序分组，日期旁显示当天全部记录的收入和支出；即使搜索只显示部分记录，日期栏仍明确标为“当日全部记录”。

### 月度与年度统计（2026-09-29）
打开“账单统计”，切换月度/年度、月份/年份以及收入/支出。显示期间总收入、总支出、结余；月图按日、年图按月，节点支持悬停、点击及键盘选择查看金额。窄屏可在图内左右滑动。分类按金额降序显示金额、占比和比例条，点击类别查看该期间对应明细；自定义分类也参与统计。

日均按所选月份已到来的天数计算，月均按所选年份已到来的月份计算（包括当前未结束月份）；无录入日期计入平均值分母，页面明确只统计已记录数据。历史月份按完整日历天数、历史年份按12个月；未来日期留空，无零除。收入和支出分开排名；占比四舍五入可能使合计略偏离100%。数据改变或恢复后，统计与明细同一快照自动更新。

这是统计及确定性事实摘要，不是模型解读；未实现消费动机推断、异常识别、订阅识别和可导出的完整分析报告。预算、资产管家、购物返现和周视图不在本轮范围。

### 月度变化分析（2026-09-29）
在“账单统计”选择月度，查看本期与上月整月的金额、增减及百分比；可切换收入/支出。按用户确定口径：已结束月对上月整月，当前月截至今日对上月整月，始终显示具体日期及记录数；本月未结束明确提示时长不同，不作整月预测。

分类表按增减绝对金额排序，包含两期类别的并集，分开展示增加与减少合计及主要来源；点击类别查看两期记录。某期完全无记录时暂不计算变化；上期有其他收支记录但所选类型金额为0时只算差额，不算百分比。所有比较只代表已记录数据，不证明真实消费减少或增加。分类变化是金额分解，不推断消费动机。跨浏览器编辑、删除、备份恢复后同一快照重新计算。年度视图暂不提供年度对比。

### 记账试用步骤
1. 在首页用虚构数据记录一笔支出 25.10 元，类别选择“礼物”，填写备注。保存后显示 ¥25.1。
2. 新增收入 100 元，观察收入、支出及结余；金额按整数分计算，最多两位小数，不自动四舍五入。
3. 选择“自定义类别”，输入“宠物”；保存后下次可直接选。类别按收入、支出分别保存，名称 1—20 字；备注选填、最多 500 字。
4. 编辑金额或类别，再删除一笔，检查月度汇总同步变化。刷新页面检查记录仍在。
5. 金额大于 0，最多 9 位整数；已发生交易的日期不晚于今天。结余仅表示该月已记录收入减支出，不是银行余额。
6. 在“记录查找”搜索分类或备注，如“礼物”“生日”，选择只看收入或支出；切换“全部月份”可跨月查找。上方金额和分类仍统计所选月份，下方单独显示匹配记录的收支合计。可直接编辑/删除搜索结果；点击“重置查找”回到所选月份全部记录。查找条件保留至当前页面关闭/刷新，跨浏览器自动更新不会清除查找条件和录入草稿。

手动账本尚无自动分类、订阅识别、异常检测、完整解释性年报或银行账单文件导入。基础统计只覆盖已记录数据。

### 原有合成银行示例
1. 查看账单，解释退款和自有账户划转的统计口径。
2. 比较产品，先选择“不能承受本金损失”：两款示例都排除。
3. 选择“可接受本金损失”和“90天”：产品B因90天持有期加2天假定到账被排除。
4. 查看陌生扣款关联卡片，预览锁卡，取消一次，状态不变。
5. 再确认锁卡，查看核验回执，刷新仍保留状态。
6. 请用户解释“锁卡是否退钱”，记录误解并填写反馈。

## 边界
本机确认不是真实客户身份认证；没有生产认证、多用户隔离或银行级授权。
哈希用于一致性检查，不是签名；本地日志不防本机文件篡改。
核验是重新读取本机模拟状态，不是独立银行背书。
有限测试通过不代表现实零风险；产品条件比较不等于完整适当性评估。
未决操作发生异常时先查询状态，不能以刷新页面代替业务确认。

## 用户反馈

- 净支出与余额的区别清楚吗？
- 产品被排除的原因清楚吗？
- 确认前知道锁卡的影响吗？
- 哪一步需要帮助？
- 上次遇到类似问题是什么时候，通常如何处理？
