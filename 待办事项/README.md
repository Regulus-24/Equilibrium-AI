## 维护约定

- 按更新日期建立 YYYY-MM-DD 文件夹。首次整理日期不代表需求首次提出日期。
- 每项使用固定编号，区分用户已提出需求、团队既定工作、助手建议和独立学习想法；进入清单不等于已批准实施或承诺本版交付。
- 当讨论产生新增、改动、暂缓、实测反馈或完成结果时，在同一轮工作中更新清单和项目记忆。这里的实时更新指随工作进展维护，不是已建立无人值守后台监控。
- 同一天更新当天文件；跨日有进展时，将尚未完成的事项承接到新日期清单，保留编号和原始来源，更新本页的当前入口。旧日期清单保留历史，不每日重复创建无变化的副本。
- 状态使用：待研究、待开展、进行中、待验证、已完成、暂缓、另窗口开展、持续事项。完成须附代码、验证或人工反馈证据；没有证据不能仅凭计划勾选完成。
- 优先级：P0为下一轮主任务，P1为近期后续，P2为后续研究，暂缓项按明确条件再启动。优先级是当前安排，可随用户反馈调整，不等于截止日。
- 与比赛弱相关的预训练、通用微调学习和AI Infra实验在独立窗口开展；只将可验证、与衡智有关的成果带回。不得据此自动创建窗口或启动实验。
- 不记录银行凭证或真实敏感账单。演示数据、内部参与者反馈和独立目标用户证据分别标识。
