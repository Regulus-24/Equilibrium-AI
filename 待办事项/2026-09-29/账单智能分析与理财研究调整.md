# 2026-09-29 账单智能分析与理财研究调整

状态：方案与待办更新，未修改应用代码，未调用模型、选定基金或创建自动监控。覆盖此前以账单问答入口为下一轮核心的建议。

## 能力事实

已有手动记账、同步/备份恢复、收支统计、趋势/分类占比、确定性月度金额增减分解。AI接入为零；智能月报/年报、自动异常识别尚未实现。增加模型调用也不自动证明分析有效，需要证据准确、可核实、有用的输出。

## 下一轮账单交付（建议顺序）

- [ ] 定义报告验收样例：正常月份、单笔大额、疑似重复、缺月、零基数、本月未结束；样例标明合成/内部/外部来源。
- [ ] 整理统一证据包：账本版本、期间、记录ID、收支/类别变化、历史样本数量、缺数据标志。计算使用整数分；全部结论仅针对已录入记录。
- [ ] 保留用户口径：历史整月对整月；本月至今对上月整月。明确两个日期范围及时长差异，不据此直接宣称节省或预测月底。
- [ ] 第一版候选检测：同类别金额偏离个人历史分布、同日同金额同类别/备注的疑似重复记录。少量数据只提示缺基线；重复记录不等于重复银行扣款；人为构造测试用于验证算法，不冒充实际检测效果。
- [ ] 接DeepSeek生成结构化月报：关键变化、依据、待核实线索、信息缺口、条件性建议；不得把备注推测变成已知消费动机。
- [ ] 校验模型引用的记录和数值，绑定快照；账本改动提示报告已过期，失败不展示为成功报告。密钥只放服务端环境配置，不入仓库；首轮使用合成账本，真实备注外发另行明确。
- [ ] 实现用户对线索的“正常/需核查/信息不足”反馈，保存对应依据与检测版本，后续核对误报/漏报。
- [ ] 验收报告数字、期间、引用、数据不足处理；比较模型解读相对现有统计新增的价值，并记录真实调用、耗时、成本。不能用文采代替效果。
- [ ] 月报稳定后扩展年报：年度变化、月份差异及大额事件依据；无全年或上年数据明确范围，不虚构同比。

报告优先入口可为“生成本期报告”，自然语言追问随后复用证据工具，不要求先做通用聊天助手。

## 五只基金研究池（意向待澄清）

用户拟以腾讯理财通为观察入口，每日了解产品动向。五只指小范围研究池，不是五只已推荐购买产品。年化10%须区分历史哪段期间、未来收益目标；稳健须明确可承受亏损与用款期限。未验证存在同时满足要求的产品。

- [ ] 澄清收益定义、研究用户的期限/损失承受范围；不把简短问答称为正式适当性测评。
- [ ] 核验实际在售情况、基金代码/份额类别、基金管理人，避免同基金A/C份额重复计作不同策略。
- [ ] 首批选择资料完整、可比较的同类候选；若跨类型，仅分组解释，不强行统一收益排行。
- [ ] 建数据字典：正式净值及日期、含分红处理的收益序列、统一区间收益/年化、最大回撤/波动/修复、基准、规模、经理任期、资产构成、费率、持有与赎回到账约定。
- [ ] 资产风险按类别展开：权益集中与行业暴露；债券信用、利率/久期等。优先说明缺数据，不编造因子或权重。
- [ ] 来源优先基金管理人正式披露；理财通用于平台展示/可售核对。公开接口及使用条件尚未验证，不假定存在可用腾讯API。
- [ ] 更新机制拟为正式净值披露后每日拉取、公告增量检查；区分估值日/发布时间/抓取时间，失败显示旧数据日期，重复抓取幂等。普通开放式基金净值不是盘中实时价格；定期持仓不能代表今日实际仓位。
- [ ] 比较先看风险与期限是否适合，再在同类、同区间比较收益及回撤等，不先拍脑袋分配权重。确有打分需求时另做依据与敏感性检验。
- [ ] DeepSeek用于解释指标、提取公告变化、回答带来源的问题；后台负责数值、时效校验与条件过滤。不凭新闻情绪预测明天涨跌或保证收益。
- [ ] 用商科/金融知识交流审阅概念，用目标用户验证理解和实际查阅价值；二者分别记录。
