# 下一轮执行清单：可核对的账单问答

日期：2026-09-29。任务状态：待开展（建议的下一轮主任务）。
依赖：已完成的HZ-001/HZ-002/HZ-020；新任务HZ-021—HZ-024及既有HZ-012/HZ-014。
本轮目标：用户用自然语言提出账单问题，系统正确调用现有计算并给出可核对答案。此清单不表示已接模型、已招募用户或已启动外部发送。

## 第一步：任务与证据基线（先做）

- [ ] A01｜整理10—15个真实表达方式的候选问题，标注是否来自团队、自拟或外部用户；不将AI生成问法冒充用户原话。产物：问题清单。建议负责：用户、顾梓洋，胡协助记录。
- [ ] A02｜先固定5种支持任务：期间总收支、类别占比、月度增减、某类别两期记录、缺数据解释；用途语义检索及金融执行列为不支持或待澄清。产物：支持范围表。
- [ ] A03｜制作隔离的2—3个月合成账本与人工核对结果，覆盖增减相抵、没有前月、只有收入、零支出、自定义类别、跨年及当前月未结束。产物：固定测试数据及答案。不得写入日常账本。
- [ ] A04｜明确退款、自有账户转入、理财本金当前无法正确区分；在测试与回答里标注适用范围。若访谈证明是核心问题，再单独设计类型及迁移，不用备注猜测。产物：数据口径及已知限制。

## 第二步：把已有程序计算封装成只读工具

- [ ] A05｜定义查询工具输入：期间、收入/支出、类别或记录ID；明确错误返回。产物：工具契约及样例。
- [ ] A06｜定义输出：期间、整数分金额、记录数、来源ID/汇总依据、账本版本、缺失数据标志、当前月对上月整月提示。产物：可回放的工具结果。
- [ ] A07｜服务端实施参数校验、允许工具列表、结果量限制和有界调用次数；不暴露编辑、删除、恢复、确认金融操作工具。产物：正常与拒绝测试。
- [ ] A08｜回答生成期间账本变化时重新查询或明确回答快照；保证同一回答中的总额和记录来自同一版本。产物：并发更新测试。

## 第三步：真正接入模型并形成可操作入口

- [ ] A09｜确认可用本地设备或获授权的模型接口、预算上限、超时与重试；记录模型版本，不硬编码密钥。没有这些条件时先完成工具与回放，不声称已接AI。产物：运行配置说明。
- [ ] A10｜接入一个只读助手，模型负责理解和表达，金额由工具提供；有歧义先澄清。产物：真实模型调用日志与可用问答入口。
- [ ] A11｜答案显示对应期间及证据入口，失败/无数据给出明确状态；避免把聊天记录写成账本。产物：前后端完整流程。
- [ ] A12｜备注被视为数据；测试“忽略规则”“删除账本”等备注内容不能改变工具权限或触发写操作。产物：拒绝与注入测试记录。
- [ ] A13｜记录耗时、工具调用成功率、超时、返回错误与模型调用量。产物：一次固定回放的性能表，未测不得填估值当结果。

## 第四步：独立验收与外部反馈

- [ ] A14｜将40题按计划划分并固定，训练/调参用例与最终验收题分开；运行前写清哪些题应回答、澄清或说明无数据。产物：版本化评测集。
- [ ] A15｜运行现有回归与新工具测试；回放问答并人工检查金额、范围、引用和权限，记录分母及全部失败题。产物：评测结果与问题清单。
- [ ] A16｜胡芷澄不看开发者操作提示独立完成3个问答任务；记录卡点并复测修复。标为内部反馈。
- [ ] A17｜用户/顾梓洋自行联系目标参与者，争取2—3次自愿试用；准备问题提纲，记录实际任务与原有方式。不由AI代发邀约。
- [ ] A18｜根据外部反馈判断第二轮先做订阅候选、异常核对还是修正数据口径；记录选择依据。没有外部反馈时保留不确定性，不补造。
- [ ] A19｜更新Demo说明、事实边界、待办状态及原始验证记录；本轮不制作PPT或审美改版。

## 完成条件

真实模型调用可复现；五种支持任务能返回有据答案，含糊/缺数据情形有正确处理；确定性回归通过；40题结果与失败列表可查；数值/期间/引用和越权约束通过；至少一次独立内部测试完成。外部招募和反馈单独记录，不因联系不上参与者就把技术功能记为未做，也不把外部验证标为完成。
